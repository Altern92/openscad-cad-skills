## A. P28 — behaviour checker (`check_behavior.py`)

- **AC-A1 (repro first).** Given a behaviour project where one body is 4 separate balls and the
  top ball is moved 5 mm away from its partner (the 2026-11-20 report), when `check_behavior.py`
  runs, then it FAILs with "separate piece … reaches none of its joint partners". If today's
  code (`loose_pieces`, P23) already FAILs, the item closes with this fixture as proof; if it
  PASSes, the root cause is found (systematic-debugging) and fixed in `loose_pieces`, not by a
  special case.
- **AC-A2.** Given the same project with all 4 balls seated, then the body PASSes (no false FAIL).
- **AC-A3 (echo from joint bodies).** Given an assembly whose angle `echo(...)` lives in a joint
  body's own `"scad"` (pulled in by `use<>`), not in the top-level `scad`, when the check runs,
  then the angle is read and checked (no "printed no ECHO" FAIL), and an angle over `max_deg`
  still FAILs. Given an echo present in neither file, then the existing "printed no ECHO" FAIL
  remains.

## B. P35 — assembly sequence (new `check_assembly_sequence.py`, gate `assembly_sequence`)

- **AC-B1.** Given `build/positioned/*.stl` of an assembly where every part can slide out along
  some straight direction without hitting the parts still present, when the check runs, then it
  PASSes and prints one removal order with each part's direction.
- **AC-B2 (negative).** Given a pin fully enclosed in a closed housing (no opening), then it FAILs
  "part pin is trapped: no straight removal direction" and exits 3.
- **AC-B3.** Directions tried: ±X, ±Y, ±Z first, then a fixed set of ≥ 26 sphere directions
  (provisional); a part moves in steps until its bounding box clears the rest; contact within
  `--clearance` (default 0.05 mm, provisional) is not a collision, so touching faces may slide.
- **AC-B4 (exceptions).** `assembly.json` (provisional name) may list `"inserted_before"` /
  `"flex"` parts with a reason; those are skipped and named in the output. Missing positioned
  STLs = SKIP with reason, never PASS.
- **AC-B5.** Wired into `validate_scad.sh --all` as `CHECK_RESULT assembly_sequence=…`, a mutant
  in `tests/mutants.tsv`, and documented in `references/validation.md`. Runtime on the 2-part
  gear example ≤ 10 s (provisional).

## C. P38 — FDM printability, first ported rules (`check_printability.py`)

Scoping report (Sonnet, 2026-11-27): their mesh code is pure numpy + trimesh (`meshops_printing`,
no B-rep); numbers verified on Hubs/Xometry pages. First batch:
1. **Build volume** — part bbox vs printer volume (default 256×256×256 mm, `--bed`; Hubs typical
   200³ VERIFIED as context).
2. **Overhang regions + area floor** — group flagged faces into regions, ignore regions < 1 mm²
   and a facet tolerance for faceted 45° cones (fixes false FAILs); Hubs 45° VERIFIED.
3. **Bridge span ≤ 5 mm** — a downward-facing horizontal region supported at both ends longer
   than 5 mm = FAIL (Hubs "unless the bridge is less than 5mm" VERIFIED).
4. **Bed contact / warping advisory** — WARN only: sharp corners on the plate face, suggest a
   45° chamfer or radius (Hubs VERIFIED).
Not FDM / not on STL (skip): trapped volumes, pins, emboss, round-hole rules (need B-rep).

- **AC-C1.** Each ported rule has a fixture with a failing part and a passing part, and a mutant.
- **AC-C2.** Each numeric threshold names its primary source in a code comment, verified on the
  source page; a number that cannot be verified is marked `◇ unverified` in the output and does
  not FAIL by itself (WARN).
- **AC-C3.** Files containing code copied from text-to-cad keep its MIT copyright and licence
  notice; rewritten code cites it as the idea source.
- **AC-C4.** Existing overhang/thin-wall behaviour and output lines unchanged (existing fixtures
  pass).
