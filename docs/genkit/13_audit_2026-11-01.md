## Findings

### F1 — Holes are counted, not "located" (CLOSED 2026-11-01)

`bracket_l` emitted only `EXPECTED_BBOX` + `EXPECTED_THROUGH_HOLES: 2`; `EXPECTED_HOLE` was emitted
**only for `boss`**.

Consequence: the P5 bug (both holes in the horizontal leg instead of one per leg) **passed all
gates** — genus matched (2), bbox matched. Fixed by hand, but:

- no declaration pinned the hole **plane**;
- no fixture would fail if the orientation changed again.

**Fixed:**
1. `emit_part.py` writes two `EXPECTED_HOLE` lines (`"Z"` and `"Y"`) with computed points.
2. `run_all.sh` gained a 4th section, "gate mutants": it builds a mutated `kit/` (both holes
   horizontal), generates, and requires the gates to **fail**.
3. Result: the real bug → `features=FAIL`, while `dimensions` and `topology` stay PASS (exactly the
   P5 situation); suite **53 passed**.

```
PASS gm_br_orientation   features=FAIL (Y-axis hole not found)
```

### F2 — AC-17 red while P1 was ✅ (CLOSED: AC rewritten)

```bash
grep -nE "translate\(\[[0-9]" kit/*.scad | wc -l   # → 10, AC required 0
```

The code is correct (`translate([0, 0, -1])` — ε for the cut; `[0, d/2 - t/2, h/2]` — derived), but
grep cannot tell a literal from an expression (`d / 2` contains the digit 2). AC-17 was rewritten as
**MANUAL** with a review criterion — the same convention the skill uses for its `MANUAL` rules.

automatic back-fill script, which would record existing errors as the "correct" size.

**GenKit action:** `docs/09` and `docs/12` point to that section.

## What it means

GenKit **kept its main promise**: declarations are generated, gates use them, tampering is caught,
generation is deterministic, refusals are honest. The weak spot was one thing: **orientation** — the
gates could see how many holes exist, not where they are.
